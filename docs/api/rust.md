# Rust

Two crates make up the Rust API:

- `texl_core` renders and loads documents. Most programs only need its
  `Engine`.
- `swan_core` implements the Swan language. You use its `Value` type to pass
  data to templates, and you can use it on its own to evaluate expressions.

This page is a guide. The API reference, generated by rustdoc from the doc
comments, documents every type and function; build and open it with:

```sh
cargo doc -p texl-core -p swan-core --no-deps --open
```

## Adding the dependencies

The crates are not published on crates.io yet. Add them from the repository:

```toml
[dependencies]
texl-core = { git = "https://github.com/onlabsorg/texl" }
swan-core = { git = "https://github.com/onlabsorg/texl" }
tokio = { version = "1", features = ["rt", "macros", "fs", "time"] }
url = "2"
```

The examples on this page use [tokio](https://tokio.rs) and
[url](https://docs.rs/url), but the engine works with any async runtime, or
with none.

## Rendering a document

```rust,ignore
use swan_core::value::Value;
use texl_core::{Engine, helpers::spawner_fn};

#[tokio::main(flavor = "current_thread")]
async fn main() {
    // The engine is single-threaded: run it on a LocalSet.
    tokio::task::LocalSet::new().run_until(async {
        let engine = Engine::new(Some(spawner_fn(|task| {
            tokio::task::spawn_local(task);
        })));
        engine.add_builtin("name", Value::Text("Ada".into()));

        let Value::Namespace(doc) = engine.render("/hello.texl", "Hello <% name %>!").await else {
            unreachable!("render always returns a document")
        };
        assert_eq!(doc.get("text"), Value::Text("Hello Ada!".into()));
    }).await;
}
```

`Engine::render(url, source)` renders a source as the document at `url`, and
returns the document: a namespace with the members `uri`, `source`, `data`
(the names the template bound), `text` (the rendered text) and `tags` (one
namespace per tag, see [Finding errors](#finding-errors)). The URL is where the
template's imports resolve from; a source with no real location, such as
standard input, can use any URL, for example a file in the working directory.

The engine and Swan values use `Rc`, so they are not `Send`, and rendering
futures must run on one thread. With tokio, that means a `LocalSet` and
`spawn_local`. The *spawner* passed to `Engine::new` is how the engine starts
background tasks, such as imports.

## Loading documents

The engine does not know how to read documents by itself. You register
*loaders*: async functions that receive a URI and return the source text, or
an error message.

```rust,ignore
use swan_core::value::Value;
use texl_core::{Engine, helpers::spawner_fn, loader_fn};
use url::Url;

async fn read_file(uri: String) -> Result<String, String> {
    let path = Url::parse(&uri)
        .ok()
        .and_then(|url| url.to_file_path().ok())
        .ok_or_else(|| format!("{uri}: not a file URL"))?;
    tokio::fs::read_to_string(&path).await.map_err(|e| e.to_string())
}

#[tokio::main(flavor = "current_thread")]
async fn main() {
    tokio::task::LocalSet::new().run_until(async {
        let engine = Engine::new(Some(spawner_fn(|task| {
            tokio::task::spawn_local(task);
        })));
        engine.add_loader("file", loader_fn(read_file));

        let path = std::fs::canonicalize("report.texl").unwrap();
        let url = Url::from_file_path(&path).unwrap();
        match engine.load(url.as_str()).await {
            Ok(Value::Namespace(doc)) => match doc.get("text") {
                Value::Text(text) => print!("{text}"),
                _ => unreachable!("a document's text is always text"),
            },
            _ => eprintln!("report.texl could not be loaded"),
        }
    }).await;
}
```

- `add_loader(scheme, loader)` handles the URIs with that scheme, such as
  `file` or `https`.
- `add_default_loader(loader)` handles URIs without a scheme. The engine
  normalizes them into absolute paths, such as `/docs/report.texl`.

A loader's future resolves to the source, either a `String` or a `Loaded`
with the *final URL* of the document, the way an HTTP redirect gives one:

```rust
use texl_core::{Loaded, loader_fn};

// `/latest.texl` is the document at `/v2.texl`
let loader = loader_fn(|uri| async move {
    match uri.as_str() {
        "/latest.texl" | "/v2.texl" => Ok(Loaded::redirected("/v2.texl", "version 2")),
        _ => Err("not found".to_string()),
    }
});
```

The document then is the one at its final URL: its `uri`, the base of its
relative imports and its identity within a rendering, so URLs with the same
final URL share one document (see
[Final URLs](../language.md#final-urls)). A loader that always fails needs a
type hint: `Err::<String, _>(...)`.

Each method does one thing: `Engine::fetch(url)` returns a `Fetched {url,
source}` (the final URL and the source) through its loader, or `Err` with an
`Undefined` value (operation `document.load`, the URL in `lhv`, the reason in
`rhv`) if no loader matches or the loader fails, `Engine::render(url, source)`
renders it, and `Engine::load(url)` is `fetch` followed by `render` at the
final URL. `load` returns `Ok` with the
document namespace, or `Err` with that `Undefined` if the document cannot be
fetched. Load a document by an absolute URI, so that the imports inside it resolve against its location. The same
loaders serve `texl.import` in templates, where a failed load gives the
same `Undefined`.

`Value` has no `Display` implementation: match on the variant to get the
text, as above.

### Caching

The engine holds configuration only: its built-ins and loaders. Every
`render` and `load` starts from a new scope and a new import cache, dropped
with the rendering. Within one rendering, each imported document is fetched
and rendered once, and concurrent imports of it share that rendering; the
next rendering fetches it again. Nothing is cached across renders: a host
that wants to wraps its loaders. Imported documents render in their own
scopes, and do not see the names of their importer.

An import that closes a cycle, such as a document importing itself, returns
`Undefined` instead of waiting forever. See
[Import cycles](../language.md#import-cycles).

## Globals and host functions

`add_builtin` binds a global, visible to every template and document of the
engine. Any `Value` works, including namespaces and functions:

```rust,ignore
use swan_core::value::{BuiltinFn, Namespace, Value};
use texl_core::{Engine, helpers::spawner_fn};

#[tokio::main(flavor = "current_thread")]
async fn main() {
    tokio::task::LocalSet::new().run_until(async {
        let engine = Engine::new(Some(spawner_fn(|task| {
            tokio::task::spawn_local(task);
        })));

        // A namespace: {name: "Ada", tags: ["admin", "dev"]}
        let mut user = Namespace::new();
        user.insert("name", Value::Text("Ada".into()));
        user.insert("tags", Value::list(vec![Value::Text("admin".into()), Value::Text("dev".into())]));
        engine.add_builtin("user", Value::Namespace(user));

        // A function. Several arguments arrive as one Value::Tuple.
        engine.add_builtin("repeat", Value::Builtin(BuiltinFn::new("repeat", |arg| {
            let items: Vec<Value> = arg.items().collect();
            match items.as_slice() {
                [Value::Text(t), Value::Numb(n)] => Value::Text(t.repeat(*n as usize).into()),
                _ => Value::undef_unary("repeat", arg),
            }
        })));

        let Value::Namespace(doc) = engine.render("/doc.texl", "<% user.name %> <% repeat (\"*\", 3) %>").await else {
            unreachable!()
        };
        assert_eq!(doc.get("text"), Value::Text("Ada ***".into()));
    }).await;
}
```

A host function receives its whole argument as one `Value`. It must not
panic: return an `Undefined` value, for example with `Value::undef_unary`, when
the argument is invalid. `Value::items` iterates over the items of a tuple,
and treats any other value as a tuple of one item.

A host that wraps its own functions as built-ins can attach the original with
`BuiltinFn::with_host_data` and read it back with `host_data`, to give the
original function back when the built-in leaves Swan. The data is opaque to
the cycle collector, so it must not hold Swan values.

### Asynchronous host functions

A host function that needs to wait returns a promise.
`helpers::promise_async` turns a future into one, and the template waits for
it:

```rust,ignore
use std::time::Duration;
use swan_core::value::{BuiltinFn, Value};
use texl_core::{Engine, helpers::{promise_async, spawner_fn, SpawnFn}};

#[tokio::main(flavor = "current_thread")]
async fn main() {
    tokio::task::LocalSet::new().run_until(async {
        let spawner: SpawnFn = spawner_fn(|task| {
            tokio::task::spawn_local(task);
        });
        let engine = Engine::new(Some(spawner.clone()));

        engine.add_builtin("slow_double", Value::Builtin(BuiltinFn::new("slow_double", move |arg| {
            promise_async(Some(&spawner), async move {
                tokio::time::sleep(Duration::from_millis(10)).await;
                match arg {
                    Value::Numb(n) => Value::Numb(n * 2.0),
                    other => Value::undef_unary("slow_double", other),
                }
            })
        })));

        let Value::Namespace(doc) = engine.render("/doc.texl", "<% slow_double 21 %>").await else {
            unreachable!()
        };
        assert_eq!(doc.get("text"), Value::Text("42".into()));
    }).await;
}
```

## Keeping names between renders

`Engine::render` uses a new scope each time. To render several templates in
the same scope, create one with `Engine::create_scope` and call
`template::render`, which returns a `template::Rendering`: the `text`, the
`data` (a snapshot of the scope bindings) and the `tags`. Such a scope is not
a document: its `texl` namespace has no `import`, so its templates cannot
import documents.

```rust,ignore
use swan_core::value::Value;
use texl_core::{Engine, helpers::spawner_fn, template};

#[tokio::main(flavor = "current_thread")]
async fn main() {
    tokio::task::LocalSet::new().run_until(async {
        let engine = Engine::new(Some(spawner_fn(|task| {
            tokio::task::spawn_local(task);
        })));
        let scope = engine.create_scope();

        template::render("<% total = 6 * 7 %>", &scope).await;
        assert_eq!(scope.get("total"), Value::Numb(42.0));
        let rendering = template::render("Total: <% total %>", &scope).await;
        assert_eq!(rendering.text, "Total: 42");
        assert_eq!(rendering.tags[0].value, Value::Numb(42.0));
    }).await;
}
```

## Without an async runtime

Pass `None` as the spawner, and the engine puts its background tasks on a
thread-local queue. Drive the rendering future yourself, and call
`helpers::run_pending` to run the queued tasks:

```rust,ignore
use std::{future::Future, pin::pin, task::{Context, Poll, Waker}};
use swan_core::value::Value;
use texl_core::{Engine, helpers::run_pending};

fn block_on<F: Future>(future: F) -> F::Output {
    let mut cx = Context::from_waker(Waker::noop());
    let mut future = pin!(future);
    loop {
        run_pending();
        if let Poll::Ready(value) = future.as_mut().poll(&mut cx) {
            return value;
        }
    }
}

fn main() {
    let engine = Engine::new(None);
    let Value::Namespace(doc) = block_on(engine.render("/doc.texl", "<% 6 * 7 %>")) else { unreachable!() };
    assert_eq!(doc.get("text"), Value::Text("42".into()));
}
```

This busy loop is fine for tests and tools whose loaders do not really wait.
For real I/O, use a runtime.

## Evaluating Swan expressions

`swan_core` evaluates Swan expressions without templates:

```rust,ignore
use swan_core::builtins::root_scope;
use swan_core::evaluator::eval;
use swan_core::lexer::Lexer;
use swan_core::parser::Parser;
use swan_core::value::Value;

fn main() {
    let scope = root_scope();
    let ast = Parser::new(Lexer::new("(1, 2, 3) => (x -> x * 10)")).parse();
    let value = eval(&ast, &scope);

    let items: Vec<Value> = value.items().collect();
    assert_eq!(items, vec![Value::Numb(10.0), Value::Numb(20.0), Value::Numb(30.0)]);
}
```

Evaluation never fails and never panics: errors are `Value::Undefined` values.
See the `swan_core` rustdoc for the pipeline and the value model, and
[Architecture](../architecture.md) for an overview.

## Finding errors

An undefined value carries an `Undef`, which explains itself:

- `Undef::describe()` gives the error in plain words, such as
  ``cannot add the text `"a"` and the number `1` ``;
- `Undef::cause()` gives the first operand that is itself undefined, so
  following it leads to the root cause;
- `Undef::pos()` is a byte offset in `Undef::expression()`, the
  `swan_core::expression::Expression` (text and origin) of the code that
  made the value. Both are `None` for values made by `undef.from`.
  A host function makes its errors with no position
  (`Value::undef_unary(op, val)`, `Value::undef_binary(op, lhv, rhv)`); the
  evaluator gives them the position of the call when the function returns
  them, or when a pending promise it returns resolves to them. To call a
  Swan value from a host function, use `swan_core::evaluator::apply`, which
  leaves the position of its errors to that call.

Swan knows only expressions. `template::render` and `Engine::render`
evaluate each tag as its own expression, whose origin is a
`texl_core::document::TagOrigin` (the document and where the tag starts).
`texl_core::document::locate(&undef)` gives the place in document terms: the
URI, the text, the byte offset `pos` in it and the start of the tag. A
function keeps the expression it was defined in, so an error inside a
function imported from another document points into that document.
`texl_core::document::members(&undef)` lists the details in document terms,
as `undef.inspect` shows them in a template. The bindings give the same text
as `source`, next to `pos`, so a host can show the code around an error.

A host that evaluates Swan code itself sets the current expression with
`swan_core::expression::with_expression` around the evaluation. Any type
that implements `Display` can be its origin; the host gets it back by
downcasting (`origin as &dyn Any`).

Each item of a document's `tags` (and of `Rendering::tags`) is a tag: its
byte span in the source (`start`, `end`), the byte span of its text in the
output (`out_start`, `out_end`), and its `value`, so a host can find an
undefined value even when its tag renders nothing.

```rust,ignore
let source = r#"Total: <% total = price * "4" %><% total %>"#;
let Value::Namespace(doc) = engine.render("/cart.texl", source).await else { unreachable!() };
let Value::Namespace(data) = doc.get("data") else { unreachable!() };
let Value::Undefined(err) = data.get("total") else { unreachable!() };
assert_eq!(err.describe(), "cannot multiply nothing by the text `\"4\"`");
let place = texl_core::document::locate(&err).unwrap();
assert_eq!(&source[place.pos..][..1], "*");
assert_eq!(place.uri.as_deref(), Some("/cart.texl"));
```

The bindings convert positions to their own unit with
`texl_core::document::utf16_offset` (JavaScript) and `char_offset`
(Python); `texl_core::engine::convert_tag_positions` does it for the tags of
a document, and with `utf16_to_byte_offset` or `char_to_byte_offset` it
converts them back when a document returns from the host.

## Memory

Swan values are reference-counted. A function holds the scope it was defined
in, so a function stored in that scope makes a reference cycle, which
reference counting alone never frees. `swan_core::gc::collect` frees the
cycles that nothing outside them refers to any more. `Engine::render` (and so
`Engine::load`) runs it when the rendering is done, so a host that only
renders documents has nothing to do. A host that evaluates Swan code itself,
with `template::render` or `eval`, calls `collect` when it has dropped what it
no longer needs.

The collector cannot see the values captured by a Rust closure. A host
function that keeps Swan values (a function, a promise, a collection) should
hold them with `BuiltinFn::capturing` rather than in its closure; otherwise a
cycle through it is never freed. See
[Memory management](../language.md#memory-management) for the details.

## API reference

The rustdoc of the two crates (`cargo doc`, see above):

- `texl_core`: `Engine`, `template::render` and `Rendering`, `document`
  (`Document`, `TagOrigin`, `locate`), loaders and the async helpers.
- `swan_core`: `Value`, `Undef`, `Namespace`, `Scope`, `Promise`,
